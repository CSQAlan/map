# 本地出行助手与手机界面

本轮采用手机优先的深青绿界面，更新首页、地点表单、底栏、路线卡和登录外观。首页步道插画仅用于介绍，不作为实际路网。老人端底栏包含：首页、路线、问助手、踩点资料、我的。助手独立于路线算法，不自动操作账号或发起求助。

## 运行本地助手

1. 在电脑上启动 Ollama 桌面程序，运行 `ollama list`，确认已安装 `qwen3.5:4b`。本项目不会自动下载模型。
2. 按 README 启动后端与前端。后端默认连接 `http://127.0.0.1:11434`，前端通过 `8000` 端口的 FastAPI 请求助手。
3. 打开 `http://localhost:5173/#/elder/assistant`，连接状态显示“本地助手已就绪”后即可提问。模型首次加载可能比后续回答慢。
4. 手机与电脑处于同一局域网时，打开电脑局域网地址的 `5173` 端口。手机不需要安装 Ollama，也不需要访问 `11434`；电脑上的前端、后端与 Ollama 应保持运行。

需要更换已安装模型时，在 `backend/.env` 设置并重启后端：

```dotenv
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_MODEL=qwen3.5:4b
OLLAMA_TIMEOUT_SECONDS=90
```

默认请求超时90秒，可配置1至180秒。单个后端 worker 最多同时处理2个聊天推理，其余请求返回“稍后再试”。连接状态探测超时4秒。模型输出限制600 token，对话历史最多保留6轮完整问答，再附加本次问题；每个用户问题最多1000字符。取消等待会终止浏览器等待，不承诺立即终止已经提交到本地模型的推理。

## 数据和功能

- 聊天只在当前助手页面的内存里保存，离开页面会取消等待并释放前端会话；不写入本地存储或数据库。
- 生成路线后，可选择“附带当前路线摘要”。只发送起终点、出行画像、距离和摘要，不发送用户身份、电话、GPS或健康问卷。
- 回答按纯文本显示。路线资料作为用户层数据发送，固定系统说明由后端提供。
- 助手用于使用指导与路线解释，不能确认实时道路安全，也不能替代现场观察。真实路线仍从“路线”页面查询。
- 离线、缺模型、超时、忙、返回内容不完整分别有可恢复提示；失败保留输入，可以编辑后发送。

## 验证命令

前后端和 Ollama 启动后，在 `frontend` 执行：

```powershell
npm test
npm run build
npm run test:ui
npm run test:assistant:live
```

`test:ui` 使用 Playwright 和电脑已安装的 Chrome，在320、390、768、1440宽度检查登录、首页、助手、条件、路线及资料页面，验证路线→导航、聊天流程，以及320/390宽度下560px高视口的输入不被底栏遮挡。为保证无数据库与地图Key也可重复运行，此测试使用API夹具，不表示真实路网通过现场核查。

`test:assistant:live` 的助手状态和聊天请求访问真实后端/Ollama；仅与助手无关的数据库页面初始化请求使用夹具。它确认真实中文答复出现在页面中。测试输出截图与JSON默认写到 `frontend/artifacts/mobile-ui/`，已忽略Git。

可以通过环境变量指定：`UI_BASE_URL`（前端地址）、`UI_OUTPUT_DIR`（输出目录）、`UI_BROWSER`（Playwright浏览器channel，默认chrome，可设msedge）。测试使用现有浏览器，不自动下载浏览器。
