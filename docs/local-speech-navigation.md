# 本地语音与途中导航

本次采用“录音 → 本地 faster-whisper → 可编辑文字 → 确认发送 → Ollama”的链路。助手不会接收音频或因转写结果自动执行操作。地点语音仅在已知地点唯一匹配时选中；无法唯一匹配时展示识别文字，保留手动选择。

## 安装与启动

项目 Python 环境包含 `faster-whisper==1.2.1` 和 `python-multipart==0.0.32`。首次使用需显式下载一次多语言 base 模型。在项目根目录：

```powershell
.\.conda\elder-map-py311\python.exe -m pip install faster-whisper==1.2.1 python-multipart==0.0.32
Push-Location backend
..\.conda\elder-map-py311\python.exe -m app.scripts.prepare_speech_model
Pop-Location
```

模型保存在根目录 `.models/faster-whisper-base/`，已被 Git 忽略。后端运行时只加载本地文件，不临时下载；CPU 使用 int8，默认4线程。可在后端环境变量指定 `SPEECH_MODEL_PATH` 与 `SPEECH_CPU_THREADS`（1–16）。下载模型需要联网，准备好后识别无需外部 ASR 服务。

后端接口：`GET /api/speech/status`、`POST /api/speech/transcribe`，上传字段为 `audio`。录音上限30秒、5MiB；在 multipart 解析之前限制请求体为5MiB+64KiB，并在解码中验证时长。识别单任务运行，繁忙时返回中文提示。应用不保存音频记录；框架解析上传时可能使用临时文件，请求结束关闭并清理。

浏览器麦克风需要 HTTPS 或本机 localhost。手机直接打开电脑的 HTTP 局域网页面时，若录音不可用，可使用“选择录音”上传短音频；正式网页部署使用 HTTPS。Android 已声明麦克风权限，仍需用户在设备上授权。不要把 PC 的 localhost 当作手机后端地址。

## 使用与播报

- 助手：点击“语音输入”，说完点击识别，也可选择已有录音。识别结果进入草稿，核对后点击发送；不自动发送。
- 出发地/目的地：使用相同录音组件，匹配选项后显示已选地点。
- 录音可取消；离开页面会停止麦克风轨道、计时器和上传等待，晚到的识别结果不会填入别的页面。
- 回答可以逐条朗读与停止。播报优先选择设备的中文本地声音，前一次播报会被新播报替换；错误会显示文字，离页停止。
- 导航默认展示文字，用户主动开启语音后播报当前段。推进或返回路段会更新台阶、坡道记录和风险提示；“休息一下”停止自动播报并暂停路段推进，继续后重播当前段。

## 地图与途中操作

当前路段、风险提示、简化或在线地图、手动完成路段依次展示。手机顶部保留求助入口，路段推进按钮在滚动时保持可达。完整指引可展开，避免长列表占据首屏。

- “已走完这段”由用户确认推进，不根据 GPS 自动假定已通过。剩余距离按路段长度比例估算；缺少长度时按段数估算，均标明为估算。
- 返回路线方案再进入同一路线保留进度；明确结束后再次开始，从首段开始。结束需要确认，立即停止播报和定位；结束不表示系统验证了到达。
- 家属状态与 SOS 使用当前段。每位老人有独立的同步队列，只保留一个待发最新快照；请求有8秒超时。服务端锁定画像行，检查快照版本，拒绝迟到旧进度。浏览器重载后从服务端冲突响应恢复版本，避免依赖设备时钟。
- 定位由用户主动开启；GPS 的 WGS84 坐标先转换成与地图路网一致的 GCJ02。定位精度差、位置过期、缺少路网时分别提示。
- 偏离提示需要连续3个不同时间戳的有效样本，精度不超过30米，且距规划路网超过 `max(40米, 2×精度)`。这仅提示用户停下核对，不自动改路线或推进进度。
- 地图初次有路网数据时适配视角；选段只改样式，位置更新只改定位标记与精度圈，不重建道路或反复缩放。提供“我的位置”“查看当前路段”“回到完整路线”。导航当前段与点击浏览的路段分别处理。
- 在线底图失败时显示简化路网及文字指引。无数据时明确说明；位置在示意图范围外时显示文字，避免蓝点消失而没有解释。

## 为什么暂不训练 AI

当前优先完善应用知识、路线摘要和地名词表；路线计算与安全约束仍由现有规划逻辑处理，助手负责解释和使用帮助。先经用户同意收集真实场景中出错的录音/转写对、地名、口音和噪声条件，建立独立评测，再判断是否换更适合的 ASR 模型或微调。单次展示录音不能证明方言识别效果，也不足以决定训练。

若后续需要不断收录采集规范、使用说明和现场变化，先考虑可追溯的资料检索。只有积累稳定、足够且可授权使用的样本后，再评估专项训练；本次没有启动训练。

## 2026-10-28 验证

- 前端单元测试：`npm test`；后端：在 backend 运行 `python -m pytest -q`。
- `npm run test:ui`：320/390/768/1440宽度，24项布局检查，4组路线/导航与助手流程。
- `npm run test:speech-navigation`：模拟浏览器录音、TTS与GPS，验证草稿确认、地点匹配、分段风险播报、休息、偏离、清理、返回保留进度与结束后重置。
- `npm run test:map`：模拟高德 SDK，验证 DOM 容器、一次初始视角、选段不重建或自动缩放、手动聚焦与异步卸载清理。
- `npm run test:speech:live`：实际上传中文 WAV，由真实 faster-whisper 转写，确认后调用实际 Ollama。默认样例路径 `.logs/speech-zh-synthetic.wav`（相对于脚本运行目录 frontend 为 `../.logs/...`），也可通过 `SPEECH_TEST_AUDIO` 指定自有录音。样例由 Windows 中文声音合成，首次加载与识别约13.8秒；“我想去”出现一个字误识别为“或想去”，地名及路线要求识别出来。此记录不作为准确率或真机测试结果。
- 浏览器脚本产物在 `frontend/artifacts/`，不进入 Git。真实手机麦克风、扬声器、户外噪声、口音、GPS轨迹及高德在线网络表现仍需实机走测。浏览器事件与模拟坐标测试不等于实地导航验证。

## 2026-11-09 语音与助手体验打磨

- 录音组件增加已录时长、剩余时长和进度条，满30秒沿用自动识别流程；取消、转写和离页时清理界面计时器。
- 等待麦克风授权和等待识别分别展示操作说明，识别期间可取消，不显示未经计算的识别进度。

- 新对话遇到未发送文字时，可保留文字后开启新对话、返回编辑或放弃文字。等待回答期间开启新对话，会先取消等待并保护恢复的草稿；录音或识别期间暂不能开启新对话。
