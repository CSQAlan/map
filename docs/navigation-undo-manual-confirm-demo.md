# 撤销误点的已走完：本地演示

## 行为与边界

普通导航刚新增一次手动标记后，出现“撤销刚才的确认”。三段路线第 1 段点击“已走完这段”后，当前第 2 段、计数 1/3；撤销后回第 1 段、计数 0/3。末段的“手动确认最后一段已走完”撤销后仍在末段，仅退回本次新增计数。到达确认与计数继续相互独立。

“上一段”仍只回看、不删计数，并清除撤销机会。重复确认已经标记过的段，不提供撤销，页面明确说明“重复确认已标记的路段不提供撤销；回看请用‘上一段’”。这可避免抹掉早先有效的标记。随后新增另一段时，只能撤销那一次新增。

回执的独立 Set 是计数来源。每次新增建立一个不可复用的内存凭据，绑定会话、路线对象、原手动索引和前进后索引。页面每个撤销按钮捕获自己的凭据，App 同步校验当前普通导航、身份权限与手动索引，回执接受撤销后页面才回原段。旧回调、伪造副本、双击、撤销后重标同一索引，以及上一个会话的凭据都不能撤销新的标记。

再手动换段或明确激活其他操作（例如文字导航、核对位置、地图浏览、保存文字路线），以及休息/暂停、绕行、打开结束弹窗、核对障碍、路线/身份/会话变化、离页/刷新，都会清掉机会。取消结束、取消障碍、继续前行不会恢复它。按钮按原生键盘顺序可达；撤销成功后焦点回进度主按钮，显示一次文字状态，不自动播报。

撤销不请求定位、相机移动或地图跟随，不写存储。索引回退只经过原有普通进度发布一次；末段撤销不发布索引进度。没有新增共享字段；回执仍只有 outcome、confirmed、total，不向家属发送手动计数、撤销凭据或定位。未改后端、接口、依赖、休息文案。原有“我不确定走到哪”、返程、到达确认、休息和绕行均保留。

## 可录的对照（约 45 秒）

使用本地合成三段路线；下面的专门浏览器脚本运行真实 App，拦截全部 API 与外网，不需要真实账号、后端或地图密钥。

- 0–10 秒：开始普通导航，展示当前第 1 段、0/3。点“已走完这段”，展示当前第 2 段、1/3 和撤销按钮。
- 10–18 秒：点“撤销刚才的确认”，展示回第 1 段、0/3；无定位或语音提示启动。
- 18–28 秒：再确认第 1 段，点“上一段”，计数仍为 1/3；重复确认第 1 段后仍为 1/3，没有撤销按钮，指出回看文案。
- 28–38 秒：确认第 2 段，再标记最后一段为 3/3；撤销后仍在第 3 段，计数 2/3。
- 38–45 秒：结束但未确认到达，回执为 2/3，返程入口保留。开始新行程，计数从零开始。可另录“打开结束弹窗→取消”，证明撤销不会复活。

```powershell

node --test --test-concurrency=4
npm run build
node scripts/check-navigation-undo-manual-confirm.mjs
```
