# 助老地图试点设计

## 目标与范围

首期服务范围限定为重庆师大试点及周边。网页与 Android App 同步试点，使用同一套 FastAPI、PostgreSQL/PostGIS 与 Redis 后端。

优先交付顺序是：先生成可在手机热点环境下访问本机后端的 APK，完成本地真机联调；随后再部署远程 Docker 服务并公开网页与 App 访问入口。

老人端首期提供大字路线推荐、基础 SOS 和危险路段上报；家属端提供基础状态查看；管理员网页负责审核和数据管理。

## 地图与数据原则

- 高德仅用于在线底图、地点搜索和地图展示，不保存、抓取或复用其地点图片和内部数据。
- Google Earth 不用于描摹、数字化或生成项目路网、楼梯、坡度等数据。
- 坡度、楼梯、扶手、路面、宽度和轮椅通行性均采用项目自有采集数据。
- 只有审核通过的路段才能参与“安全路线”推荐；未知和待审核路段不作为安全承诺。
- 若起终点之间不存在已核验的连续路线，产品应明确提示“暂无可验证安全路线”，而不能强行推荐。

## 采集与审核闭环

采集人可以是项目组、志愿者、老人或家属。所有非管理员上报均进入待审核状态，不会立即影响路线。

一次上报包括：当前定位、1–3 张自有现场照片、是否有楼梯、是否有扶手、轮椅是否可通行、路面类型、宽度、观察到的坡度情况与文字备注。

管理员审核通过后，将采集值写入路段的当前有效属性，同时保存采集记录、审核人、审核时间、照片和前后差异。被驳回的记录保留原因；旧数据可在设施变化后重新上报并过期。

## 网页与 Android App

网页与 Android App 共用 Vue 页面和同一套 API。Android 使用 Capacitor 的原生定位与拍照能力；浏览器版本使用相应 Web 能力。

App 验收要求：

- 老人端功能和网页端一致，且定位、拍照、权限提示不弱于网页；
- 不依赖电脑或局域网即可访问远程版本；
- 弱网时保留最近一次成功路线并展示明确提示；
- 至少两台 Android 真机完成字体、触控、定位、拍照、地图缩放和 SOS 测试。

如果 Android WebView 内的高德地图手势、定位或渲染体验不达标，地图层将替换为原生高德地图适配层，其他页面和 API 不重写。

## 部署架构

远程生产环境使用 Docker Compose 部署 HTTPS 反向代理、FastAPI、PostgreSQL/PostGIS、Redis 与对象存储。网页、Android App 和管理员后台访问同一 API；数据库和对象存储不直接向公网暴露。

现场照片保存于对象存储，数据库只保存地址、元数据与审核状态。生产环境启用 HTTPS、正式鉴权、角色权限、操作日志与每日数据库/照片备份。

## 实施阶段

### 阶段 0：本地 APK 联调优先

1. 填写本机局域网 API 地址，构建 Android debug APK。
2. 手机连接电脑热点，启动本地 FastAPI、PostGIS 和前端联调服务。
3. 在真机验证登录、地图、定位、路线、拍照上报与 SOS。
4. 修复本地网络、CORS、Android 权限与地图兼容问题。

### 阶段 1：试点数据闭环

1. 实现自有照片上传和对象存储。
2. 实现待核验路段任务、极简上报和审核差异记录。
3. 只以已审核路段生成安全路线，并处理路线断连提示。

### 阶段 2：远程部署与同步试点

1. 部署 Docker 生产栈、域名和 HTTPS。
2. 配置正式 API、高德 Key、CORS、备份与日志。
3. 发布公网网页与 Android APK，进行两台以上真机验收。

## 计划性排除项

- 不使用 Google Earth 或其他地图影像来构建项目路网数据。
- 不使用未经审核的自动坡度、楼梯推断结果。
- 不保存高德地点图片或把其作为项目证据。
- 首期不做后台持续位置追踪。
