# 助老地图前端界面统一改进设计

## 目标

统一助老地图现有前端的视觉与页面结构，同时分别为手机和电脑安排合适的任务布局。手机不再把桌面双栏页面压窄或把所有任务堆在一张长页里；页面按任务拆分，必要时自然滚动，不使用固定高度裁切内容。电脑利用更宽的视口呈现导航、任务内容和地图的并列关系。

面向老人、家属和管理员三种角色。老人端以“找到目的地、选路线、开始导航”为首要任务；家属端突出老人状态与告警；管理员端突出审核和地图落点。保留当前业务功能、接口、地图数据和“大学城踩点资料与正式导航路网相隔离”的规则。

## 已确认的设计选择

- 视觉方向：B「城市蓝」，清晰、克制、偏公共服务气质。
- 页面结构：A「分页面任务流」。首页、路线方案、导航分别承担单一任务；家属和管理员使用适合自身工作的角色外壳。
- 手机与桌面采用同一套设计语言，但不强求同一布局缩放适配。
- 目前设计阶段不改产品代码、不改变后端 API，也不引入与界面目标无关的业务功能。

## 视觉规范

### 色彩

| Token | 色值 | 用途 |
|---|---|---|
| 深海墨 | `#203747` | 正文、标题、主要文字 |
| 导览蓝 | `#286887` | 主按钮、选中状态、导航路线 |
| 浅雾蓝 | `#E5EFF3` | 次级强调、轻量操作背景 |
| 雾白 | `#F3F6F8` | 页面背景 |
| 纸白 | `#FFFFFF` | 内容表面、输入框 |
| 安全琥珀 | `#A96819` | 台阶、风险等谨慎提示，不表示可通行 |

除风险提示外不增加装饰性强调色；地图底色维持低对比度，导览蓝作为路线与当前操作的视觉焦点。错误、成功等语义状态可使用符合对比度要求的语义色，但不扩充为装饰色。

### 字体、尺寸和表面

- 使用系统中文字体栈（系统 UI、微软雅黑、苹方回退），不依赖在线字体或外部字体下载。
- 页面标题约 26–32px，区块标题约 20–24px，正文 16–18px，辅助说明不低于 14px；正文行高约 1.5。
- 主要触控目标至少 48px 高，常用主按钮 52–56px；键盘操作保留清晰焦点环。
- 字段使用约 8px 圆角，内容面板约 12–16px；用留白、排版和边界表达层级，不把每块内容都做成卡片或叠加阴影。
- 不使用大面积渐变、装饰动画或仅靠颜色区分的重要状态；尊重减少动态效果设置。

## 页面结构与导航

使用 Vue Router 的 hash history，使页面切换、浏览器返回和静态托管下的 URL 行为明确，并兼容 Capacitor WebView。保留现有 `#/admin` 入口的兼容重定向。

### 老人/访客页面流

```text
首页（地点输入）
  → 路线方案（候选路线比较）
    → 导航中（地图 + 下一步提示；专注模式）

主导航入口： 首页 | 路线 | 踩点资料 | 我的
```

- 手机主导航只出现在一级页面；路线详情、地点选择等子任务显示返回入口，不重复占用底部空间。
- 开始导航后隐藏主导航，显示清晰的返回/结束控制、路线地图、下一步文字和紧急求助操作。
- 电脑端通过左侧导航切换主要入口。路线方案页采用路线内容与地图并列，建议内容约 40%、地图约 60%；导航中使用地图为主、指令面板为辅。
- 踩点资料继续保持独立入口、地图优先和“待核查、不参与路线推荐”的说明；未定位记录仍在列表中，不伪造地图点位。

### 家属和管理员

- 家属端使用自己的页面外壳，首页优先显示老人当前状态、最后更新时间及告警；绑定流程作为明确的子页面。
- 管理端桌面使用侧边导航和主工作区；手机切换为紧凑顶部菜单/可滚动导航，审核和补点各自独立成页。
- 不把老人端的底部四项导航强加给家属和管理员；角色间共用按钮、表单、提示、照片查看器等基础规范。

### 视口适配

- 小屏（约 320–767px）：单栏、触控优先、页面按内容自然增长；有底部导航的页面为其预留安全区。不得以固定 `height` 隐藏表单或说明。
- 中屏（约 768–1023px）：使用紧凑导航和可收缩双栏，避免狭窄时地图与文字互相挤压。
- 宽屏（约 1024px 起）：角色侧栏 + 主内容；地图与路线/资料面板按任务并排。主要内容最大宽度约 1440px。
- 所有断点下均可纵向滚动；横向滚动只允许出现在确有宽表格的管理员数据区域，并提供合适的可访问说明。

## 组件与代码边界

### 页面外壳

```text
App.vue（路由出口、全局弹层）
├─ ElderLayout（老人/访客导航与内容区）
│  ├─ ElderHomePage
│  ├─ RoutePlanPage / RouteOptionsPage
│  ├─ NavigationPage（专注地图）
│  ├─ SurveyRecordsPage
│  └─ ProfilePage
├─ FamilyLayout（家属导航与内容区）
│  ├─ FamilyDashboardPage
│  └─ FamilyBindingPage
└─ AdminLayout（管理员导航与内容区）
   ├─ AdminOverviewPage
   ├─ CollectionReviewPage
   └─ SurveyPlacementPage
```

登录、访客资料和首次画像/健康问卷为独立认证或对话流程，不能遮盖关键错误提示，也不能在页面拆分时丢失现有提交流程。

### 组件分层

- `components/ui/`：页面标题、主次按钮、表单字段、地点输入、状态提示、确认弹窗、照片查看器等稳定基础组件。
- `components/elder/`：路线偏好、路线比较卡、地图画布、导航指令面板、紧急求助操作。
- `components/family/`：老人状态卡、告警列表、绑定状态。
- `components/admin/`：审核表、审核详情、地图落点面板、媒体对照视图。
- `layouts/`：老人/访客、家属、管理员三种响应式外壳。
- `pages/`：页面级编排，只组合组件并处理页面级状态，不承担所有网络请求。
- `composables/` 与 `services/`：分别封装角色会话、路线规划、地图数据、踩点资料、家属监控和 HTTP/API 调用。

`App.vue` 收敛为路由视图、全局对话框和跨页提示的组装层。优先复用 Vue 3 Composition API 与现有服务；不为了拆文件而引入 Pinia 等额外状态库。CSS 拆为 design tokens/base、角色布局和组件/页面局部样式，逐步移除当前集中在一个 `styles.css` 中的重复断点规则。

## 行为和数据约束

- 保留现有 FastAPI 路径、请求结构、地图坐标处理和错误语义；本轮不做 API 或数据库迁移。
- 继续保护管理员登录、待审列表、审核和手动落点所需的 bearer token；重构后所有管理请求继续携带 token。
- 采集者提交记录仍可公开使用现有流程；只有管理员读取待审核详情、审核或管理位置。
- 现有路线推荐的数据、排序、画像偏好、紧急求助、家属监控和采集审核流程均不得因页面切换而丢失状态或重复提交。
- 登录失败、地图加载失败、空记录、待定位记录、接口不可用等状态在各自页面可见且给出明确下一步；地图失败时允许继续查看非地图内容。

## 验收标准

1. 首页、路线方案、导航、踩点资料、家属页面和管理员页面均能按角色外壳正常到达；浏览器返回和 `#/admin` 兼容行为可用。
2. 在 320px 窄屏下没有整页横向溢出，重要按钮不被导航栏或安全区遮挡；内容过长时页面可滚动且不被固定高度裁切。
3. 在桌面宽屏中角色侧栏、主要内容和地图各自有明确层级；路线比较与地图可以并列查看。
4. 所有现存业务请求维持既有 API 契约；管理员请求仍携带 token；访客/采集提交及老人路线体验无回归。
5. 地图/数据加载失败、空状态、错误提示、键盘焦点和减少动态效果均经过手工检查。
6. 前端生产构建通过；如环境可用，执行现有前端测试及 Android WebView/同步验证。设计方案不把 APK 构建成功作为本次视觉规范的前置条件。

## 明确不做

- 不改变地图供应商、地图坐标系、路线算法、后端鉴权或数据库结构。
- 不把踩点资料并入正式导航路网，也不把尚未核查的资料展示成通行安全承诺。
- 不为视觉效果新增外部图片字体服务、复杂动画、装饰性渐变或大量图标依赖。
- 不在用户确认实施计划前修改产品代码。
