## 架构与行为
仅修改 createRoutePlanner 的状态边界及测试，不改页面、数据库和接口。每次规划获得递增序号，只有当前序号能提交结果、错误和 finally 的加载状态。输入起点、终点、画像或策略发生变化时，通过同步 watch 递增序号、清空候选路线、风险、选中路段和错误，结束过期加载并提示重新生成。保持直接 ref 赋值和现有 select 方法兼容。

规划前先校验并规范化地点，再取得请求序号并进入加载状态，避免同步 watch 把规范化误判成用户修改。每次规划开始清空旧结果；等待期间无法用旧路线开始导航。无效条件也必须使此前请求失效。空输入不能通过模糊匹配自动成为第一个地点。

过期请求成功、HTTP 失败、网络异常或 JSON 解析延迟均返回 false 且不影响当前状态；不要求取消网络请求，不增加依赖。有效请求保持既有风险说明和错误信息。失败清空选中路段，保留输入。保持 URL 和画像/策略参数契约。

## 验证
使用 deferred Promise 控制两次请求及 JSON 的返回顺序，覆盖旧成功覆盖新成功、旧失败清空新结果、旧 finally 提前结束加载、画像/策略/起终点变化、无效新输入、导航期间旧结果、空地点及规范化输入。执行全部前端测试、生产构建和 git diff --check。
