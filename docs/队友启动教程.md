# 助老地图：队友本地启动教程

适用环境：Windows + PowerShell。本文用于在自己电脑上启动项目、查看网页及局域网手机演示，不包含正式服务器部署或 Android 打包。

文档更新：2026-11-09。步骤根据当前项目配置与脚本整理，本轮没有重新执行安装、启动或测试。

## 1. 准备软件与项目

先安装以下软件：

| 软件 | 用途 |
| --- | --- |
| Node.js 22.12 或更高的兼容版本，建议 Node.js 22 LTS | 运行前端，附带 npm |
| Miniconda 或 Anaconda | 创建 Python 3.11 环境 |
| Docker Desktop | 运行 PostgreSQL / PostGIS 数据库，使用 Linux 容器 |
| Ollama（可选） | 运行本地文字助手 |

安装后重新打开终端。Conda 命令不可用时，可使用安装软件附带、已经初始化 Conda 的 PowerShell 终端。

获取完整项目代码并解压到自己的目录。下文以 `F:\items\map` 为例；如果你的目录不同，只需把每次 `Set-Location` 中的项目路径替换为自己的路径。

```powershell
Set-Location F:\items\map
node --version
npm.cmd --version
conda --version
docker --version
```

项目根目录应能看到 `backend`、`frontend`、`scripts`、`environment.yml` 和 `docker-compose.postgis.yml`。

不要直接复制其他电脑的 `.conda` 或 `node_modules`；按下面步骤安装。仅分享已提交的 Git 代码时，未提交的修改不会包含在内。

## 2. 首次安装依赖

以下命令均从项目根目录开始。首次安装需要联网。

### 2.1 创建项目内的 Python 环境

```powershell
Set-Location F:\items\map
conda env create --prefix .\.conda\elder-map-py311 --file .\environment.yml
```

必须使用这个项目内路径，因为现有启动脚本直接调用 `.conda\elder-map-py311\python.exe`。只创建同名的全局 Conda 环境，启动脚本仍找不到它。

如果这个路径的环境已经创建，后续同步依赖使用：

```powershell
conda env update --prefix .\.conda\elder-map-py311 --file .\environment.yml
```

后续命令直接调用环境中的 Python，不要求每个终端都执行 `conda activate`。

### 2.2 安装前端依赖

```powershell
Push-Location .\frontend
npm.cmd ci
Pop-Location
```

`npm.cmd ci` 按项目的 `package-lock.json` 安装依赖。若提示锁文件与依赖不一致，先确认代码和锁文件来自同一版本，不要直接删除锁文件。

### 2.3 创建本地配置和日志目录

```powershell
if (!(Test-Path .\backend\.env)) {
    Copy-Item .\backend\.env.example .\backend\.env
}
if (!(Test-Path .\frontend\.env.local)) {
    Copy-Item .\frontend\.env.example .\frontend\.env.local
}
New-Item -ItemType Directory -Force .\.logs | Out-Null
```

这些命令保留已有配置。`.env`、`.env.local` 不进入 Git，也不会随代码自动分发给队友。

后端默认数据库配置为：

```dotenv
DATABASE_URL=postgresql+psycopg://postgres:postgres@127.0.0.1:5432/elder_map
```

它与项目 Docker 配置一致。先保持默认即可；如果自己修改数据库端口或密码，需要同步修改此处。默认凭据仅用于本地演示。

## 3. 启动数据库并初始化数据

先打开 Docker Desktop，等待引擎就绪，再在项目根目录执行：

```powershell
docker compose -f .\docker-compose.postgis.yml up -d
docker compose -f .\docker-compose.postgis.yml ps
```

等待数据库显示 `healthy`；刚启动时可能先显示 `starting`，稍等后再次执行 `ps` 查看。

然后初始化表结构、试点路网、地点和踩点资料：

```powershell
Push-Location .\backend
..\.conda\elder-map-py311\python.exe -m app.scripts.init_map_data
Pop-Location
```

成功时终端会输出包含 `areas`、`nodes`、`pois`、`segments` 等字段的数量信息。数据库数据保存在 Docker 卷中，不会仅因重启电脑消失。

首次使用必须初始化；普通日常启动不必重复导入。更新种子数据后可按项目说明再次运行初始化脚本。

## 4. 启动前后端

打开两个 PowerShell 窗口，分别执行，运行期间保持窗口开启。

窗口一：启动后端。

```powershell
Set-Location F:\items\map
.\scripts\start-backend.cmd
```

窗口二：启动前端。

```powershell
Set-Location F:\items\map
.\scripts\start-frontend.cmd
```

也可在完成首次安装后，从项目根目录执行 `.\scripts\launch-dev.cmd`，一次打开两个启动窗口。

现有脚本将输出重定向到日志文件，窗口没有持续打印内容是正常的。出错时查看项目根目录的：

- `.logs/backend.log`、`.logs/backend.err`
- `.logs/frontend.log`、`.logs/frontend.err`

浏览器打开以下地址：

| 地址 | 内容 |
| --- | --- |
| `http://127.0.0.1:5173/` | 项目网页 |
| `http://127.0.0.1:8000/` | 后端基本状态，正常时返回含 `status: ok` 的 JSON |
| `http://127.0.0.1:8000/docs` | 后端 API 文档 |

后端根地址能打开只表示服务已响应，不能单独证明数据库、助手或语音模型已就绪。

## 5. 可选：开启本地文字助手

只看首页和路线不需要先准备 Ollama。需要展示“问助手”时，再完成本节。

安装并启动 Ollama，在终端查看已安装模型：

```powershell
ollama list
```

项目默认使用 `qwen3.5:4b`。如果还没有该模型，可在有网络、足够磁盘空间的情况下显式下载：

```powershell
ollama pull qwen3.5:4b
```

保持 Ollama 运行，确认 `backend/.env` 中以下配置与本机一致：

```dotenv
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_MODEL=qwen3.5:4b
OLLAMA_TIMEOUT_SECONDS=90
```

也可以把 `OLLAMA_MODEL` 改为 `ollama list` 中已安装的兼容聊天模型名称。修改后重启后端。

进入网页“问助手”，或直接打开 `http://127.0.0.1:5173/#/elder/assistant`。首次模型加载可能较慢。手机通过电脑后端使用助手，不需要在手机安装 Ollama。

## 6. 可选：开启语音转文字

项目环境已经声明 `faster-whisper==1.2.1` 和 `python-multipart==0.0.32`，按第2节安装后无需重复安装。

在项目根目录执行一次模型准备命令，需要联网下载：

```powershell
Push-Location .\backend
..\.conda\elder-map-py311\python.exe -m app.scripts.prepare_speech_model
Pop-Location
```

模型默认保存在 `.models/faster-whisper-base/`，不进入 Git。队友从代码仓库获取项目后，需要自行准备模型；后端运行时不会自动下载。下载完成后可以重启后端，再使用网页语音输入。

使用流程：点击“语音输入” → 允许麦克风 → 说完点击识别 → 核对或修改文字 → 主动点击发送。单次最多30秒、5MiB，也可以“选择录音”上传已有短音频。

语音转文字与 Ollama 是两个独立功能：识别录音需要本地语音模型，生成助手回答还需要 Ollama。回答朗读使用设备语音能力，不需要额外安装 Ollama 语音模型。

## 7. 可选：配置在线地图

编辑 `frontend/.env.local`，填入自己的高德 Web 端 JS API Key 和安全密钥：

```dotenv
VITE_AMAP_KEY=你的Web端JSAPIKey
VITE_AMAP_SECURITY_CODE=你的安全密钥
```

按高德控制台要求配置允许访问的域名，修改后重启前端。未配置或加载失败时，项目提供简化路网与文字指引；简化路网不是完整离线底图。

首次演示可以先不填 Key，先看基础路线和页面流程。

## 8. 手机在同一局域网访问

1. 电脑和手机连接同一 Wi-Fi，电脑保持数据库、前端和后端运行。
2. 电脑执行 `ipconfig`，查找当前联网适配器的 IPv4 地址，例如 `192.168.1.10`。
3. 手机浏览器打开 `http://192.168.1.10:5173/`，把示例地址换成电脑实际 IP。
4. 如被防火墙阻止，在可信的专用网络下允许前端和后端的 `5173`、`8000` 端口访问，无需关闭整个防火墙。

网页默认把当前访问主机的 `8000` 端口作为后端地址。通常不用额外配置 `VITE_API_BASE_URL`；若自己设置过这个变量，请确认它没有指向手机自己的 `localhost`。

手机中的 `127.0.0.1` / `localhost` 代表手机自己，不能拿来访问电脑后端。数据库和 Ollama 保持仅供电脑本地使用，无需向手机开放 `5432` 或 `11434`。

普通 HTTP 局域网页面可能无法使用麦克风和定位。可以先用“选择录音”上传音频；完整浏览器麦克风与定位体验需要合适的 HTTPS 环境。电脑本机可以使用 `http://localhost:5173/` 体验录音。

## 9. 给队友演示时的建议顺序

1. 打开首页，按页面提示选择体验方式或使用演示资料登录，不填写真实个人信息。
2. 从已有地点中选择出发地、目的地，按实际出行情况选择画像和路线策略。
3. 查询路线，查看路线说明，再进入分段导航。
4. 展示“已走完这段”“休息一下”“继续前行”和结束确认；路段推进由用户确认，不是 GPS 自动判定到达。
5. 配好 Ollama 后展示文字助手；准备好语音模型后再展示录音、核对文字和确认发送。

当前导航是试点演示，真实手机录音、户外定位与实地路况仍需后续走测。2026-11-09 新增的录音计时与草稿保护仅完成代码修改和源代码审阅，尚未运行验证。

## 10. 下次启动与停止

首次安装完成后，日常从项目根目录执行：

```powershell
Set-Location F:\items\map
docker compose -f .\docker-compose.postgis.yml up -d
.\scripts\launch-dev.cmd
```

使用助手时另外保持 Ollama 运行。无需每次安装依赖、初始化数据或下载模型。

结束时，在前后端各自窗口按 `Ctrl+C`，按终端提示结束任务。若也要停止数据库：

```powershell
docker compose -f .\docker-compose.postgis.yml stop
```

`stop` 保留数据。不要为了普通重启执行删除数据库卷的命令。

## 11. 常见问题

| 现象 | 优先处理 |
| --- | --- |
| 找不到 `python.exe` | 确认环境创建在项目 `.conda/elder-map-py311`，而不是全局同名环境 |
| 日志重定向失败、路径不存在 | 在项目根目录创建 `.logs` 后再启动 |
| `npm` 提示 PowerShell 脚本执行受限 | 使用本文的 `npm.cmd` 命令，无需修改系统执行策略 |
| Docker 连接失败 | 打开 Docker Desktop，等待引擎就绪，确认使用 Linux 容器 |
| 数据库连接失败 | 查看 Compose 状态是否健康，确认 `5432` 未被其他数据库占用，以及 `.env` 连接信息一致 |
| 页面能打开但没有地点或路线 | 确认后端运行，并完成第3节数据库初始化 |
| 手机页面能打开但接口失败 | 检查电脑 `8000` 端口、专用网络防火墙、Wi-Fi 客户端隔离及自定义 API 地址 |
| 本地助手不可用 | 查看 `ollama list`、Ollama 运行状态、后端模型名称；更改配置后重启后端 |
| 提示缺少语音模型 | 在项目根目录按第6节执行模型准备命令，检查是否自定义了 `SPEECH_MODEL_PATH` |
| 手机无法录音或定位 | 检查是否为普通 HTTP 局域网访问，参照第8节处理 |
| 地图未加载 | 检查 Key、安全密钥与允许域名；也可以先使用简化路网 |
| 修改环境变量没有生效 | 停止并重新启动对应前端或后端进程 |
| 端口被占用 | 先停止已有的项目进程；若自行改端口，也要同步 API 地址和 CORS 配置 |

更多细节见 [本地语音与途中导航说明](local-speech-navigation.md) 和 [本地助手说明](local-assistant.md)。
