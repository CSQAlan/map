# 本机双端绑定与共享演示

**仅演示，测试角色，无真实数据。不是正式功能，不是身份认证。**

## 独立方案与实施边界

两个角色页 → 一个加锁的进程内状态 → 直接调用现有 `family_consent_policy.apply` 和 `can_view_location`。不复制授权规则，不导入主应用、配置、数据库，不接入生产打包或现有开关。不保存文件、浏览器缓存或 cookie；页面每 750ms 读取本机状态，网络失败清除共享显示，旧请求通过序号和修订号保护。

实施顺序：核对基线与现有规则；新增标准库服务和两个角色页；合成测试覆盖配对、独立同意、撤销、过期、重放及 HTTP 边界；运行既有规则与本地 Chrome 双页验证；关闭自建进程并检查差异。

页面采用白色阅读区、浅蓝背景 `#edf3f7`、深蓝正文 `#163247`、蓝色操作 `#155f80`、撤销红 `#853d37` 和黄色警示 `#f9dfa0`。系统中文字体、大字单列、明确按钮，不使用地图、外部字体或装饰动画。突出的是绑定与共享的区别，不是通用仪表盘。

## 启动和停止（PowerShell，仓库根目录）

```powershell
& .\.conda\elder-map-py311\python.exe -B .\tools\family-consent-demo\server.py --port 8787
```

老人页：<http://127.0.0.1:8787/elder>；家属页：<http://127.0.0.1:8787/family>。必须在同一台电脑上打开两个标签，不支持手机或局域网。只能监听 127.0.0.1，不能指定其他主机。端口占用时启动失败，可换独立端口（例如 `--port 8788`）。停止：在启动终端按 **Ctrl+C**；进程退出即丢弃全部状态。

老人生成 120 秒一次性演示邀请码，复制到家属页并发送申请；老人明确确认绑定后，家属仍看不到共享。老人另按“单独开启共享”才显示模拟状态文字，无 GPS 或位置。任一角色撤销后共享消失，绑定保留。再次共享必须生成新邀请并重新确认、授权。邀请到期阻止接受和确认；已在有效期确认的当前配对，允许老人之后首次明确授权，完全遵循现有规则。

## 本地验证

邀请码响应隔离修复：家属 JSON 不返回 `code`、`invitation_id` 或 `pair_id`。只有老人页出示邀请码，家属手动输入申请；家属撤销使用独立随机的 `pair_ref`，它不是邀请码，也不能输入后发起申请，并且旧引用不能操作新配对。这只隔离角色响应，不是身份认证，测试角色仍可自由切换。

本次修复验收：既有规则 59 项、demo unittest 8 项均通过；新增测试逐一检查初发、申请、确认、授权、撤销刷新、续邀及错误响应的完整 JSON，不包含已生成的邀请码值。Chrome 本次检查了 41 个完整家属响应，无三个生成的邀请码值或同值 ID 别名，原有双页、3 秒超时、慢请求和旧响应检查均通过。命令仍为下列命令，退出码全部 0；修复前新增回归测试先失败（退出 1）。测试临时进程均已退出。下段 7 项记录为初版验收历史。

未验证真机、真实 GPS、生产身份、数据库、多进程事务、主应用或 APK；这些均不属于本演示。邀请过期采用 Python 合成时钟验证，未在浏览器中等待真实 120 秒。

## 限制

两个路径是任意可切换的测试角色，不可信身份。演示邀请码不是正式凭证，不收集真实姓名、手机号或坐标，没有真实位置发布/查询。进程锁只演示单进程串行更新，不替代生产事务。网页轮询通常存在约 750ms 加请求时间的状态同步延迟，不是即时推送；检测到网络失败或超时才清除显示，后台标签浏览器节流可能延长同步。不应放入任何真实数据。

读取采用串行轮询；请求含响应体读取的超时为 3 秒，失败或超时清空显示，不承诺断网瞬间即可检测。后台标签浏览器节流还可能延长检测时间。

上线还需可信主体认证、服务端验证并绑定双方的不可猜测邀请、原子一次性消费/CAS、持久化撤销及审计、防滥用与真正位置接口的逐次鉴权。本演示不能替代上述条件；既有 P0 默认关闭保持不变。
